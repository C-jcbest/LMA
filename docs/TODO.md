## 实施总原则

- 智能体依据用户目标和实际证据动态决定工具、时间窗、粒度、复核次数与回答结构；以下方案是能力与验收边界，不是固定执行模板。
- 保持 Thread/Checkpoint 为会话历史唯一事实来源；模型输入、工具结果和前端展示状态各自职责单一。
- 先做可独立回归的小改动，再做流式与地图两项高风险重构。建议顺序：11、12 → 9、10 → 8 → 13。
- 每项均需覆盖正常、失败、缺测/空值和恢复场景；未完成代码、测试与文档同步前不得标记完成。

8. [待实现] **重构前端 LangGraph Streaming**

   方案：

   - 引入与当前 SDK 兼容的 `@langchain/react`，以 `useStream` 绑定 `threadId`；先建立薄适配层兼容现有消息卡片，再移除 `streamStates`、`runIdsRef`、`abortControllersRef`、`truncateAfterLastUser` 和手工 checkpoint/stream 去重。
   - 切换会话调用 `disconnect()`（等价于不取消 Run 的断开），目标会话按 `threadId` 重新挂载并 rejoin；Stop 使用 `stop()` 或服务端 cancel，明确取消 Run。
   - 正文、工具调用和推荐动作都从服务端消息/状态派生；前端只保留选中项、展开态等 UI 状态。侧栏运行态从服务端线程/Run 状态获取，不以本地缓冲是否存在作为事实。
   - 采用渐进迁移：先建立集成测试覆盖现有行为，再替换单会话流，最后删除旧状态机；不一次性重写消息卡片。

   验收：

   - 生成中切换会话不会取消后台 Run；切回或刷新页面后可恢复工具卡、已生成正文和后续 token，且无重复消息。
   - Stop 后服务端 Run 确实结束；多个 Thread 并行时状态互不串线。
   - 断网重连超时后回退拉取 Thread 历史，最终界面与 checkpoint 一致。

9. [待实现] **为工具执行引入 LangGraph RetryPolicy**

   方案：

   - 先调整 `ToolNode(handle_tool_errors=True)` 吞异常的现状：瞬时网络异常必须向节点层冒泡，参数/权限/业务错误转换为可读的 ToolMessage，不进入重试。
   - 在 `tools` 节点配置 `RetryPolicy(max_attempts=3, initial_interval=0.5, backoff_factor=2, jitter=True)`，`retry_on` 仅接受超时、连接错误和明确的 HTTP 5xx/429；北斗业务码、4xx、校验错误和空数据不重试。
   - 视觉模型的 JSON/图像降级重试继续保留为“语义修复”，与节点级网络重试分开计数，避免重试放大。

   验收：模拟瞬时失败后可恢复；不可重试错误只执行一次；达到上限后智能体收到可解释错误；日志含工具名、尝试次数和错误类别但不含凭据。
