# 0008：复用巡检与登记结论的问题推荐

- 日期：2026-11-13
- 状态：有效

> 决策记录保存当时的背景与理由，是历史，不是现行规则的来源。现行架构见 [architecture.md](../architecture.md)；被取代的内容以后续记录为准。

- 推荐入口保持独立的 POST /suggestions，不创建会话、运行工具或重新查询平台。SessionStorage.suggestion_sources 用一次 SQL 取得最多 4 个巡检候选和 2 个额外调查候选，每点最近 2 条未归档登记结论；不读 trend、原始序列、图片、用户提问或 checkpoint。未登记的自然回答不是结论摘要，推荐不补做历史总结。
- suggestion_context 保留测点 UUID、名称/分组、窗口和方向有效跨度、长期变化、质量、初筛理由、历史结论及记录时间。模型只选择来源 UUID、窗口键和问题主体；服务端绑定名称和日期，同名时附 UUID，丢弃不存在的引用。主体的语义与证据匹配由模型及真实输出验收负责，不用关键词或正则充当语义判断。
- 单 worker 的 SuggestionService 以规范化摘要内容与北京时间日期为版本，最多保留 8 个版本、同时生成最多 2 个不同版本；同版本请求共享任务。每个请求仍读有界来源核对版本，生成完成后再次核对，期间更新或删除不返回旧问题。仅成功结果（含主动少展示）缓存，异常不缓存、不自动重试。生成限时 12 秒，API 总限时 15 秒；取消一个请求不取消其他请求共享的生成，应用关闭统一取消并等待清理。归档会话仍可在原有历史入口查看，但其结论不用于新调查推荐；取消归档后可重新入选。账号/平台配置属于进程配置，变更后重启同时清空缓存；未增加多租户缓存。
- 模型构造移到工作线程，推荐由欢迎页原有 effect 异步请求；未增加首屏等待、预热或前端结果缓存。缓存不替代监测事实，新日期重新选择时仍明确展示原始历史范围。验收记录见[推荐改进验收](../reviews/suggestion-review-2026-11-13.md)。
