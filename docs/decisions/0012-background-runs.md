# 0012：调查在后台运行，工具结果只存于 checkpoint

- 日期：2026-11-17
- 状态：已接受；取代 [0004](0004-evidence-transactions.md) 的工具边界存证部分

> 决策记录保存当时的背景与理由，是历史，不是现行规则的来源。现行架构见 [architecture.md](../architecture.md)。

## 背景

后端全面检查发现：调查在 SSE 生成器里执行，浏览器刷新、关闭或网络中断都会取消调查，与界面“可先离开，调查会继续”的提示不符，也无法在刷新后接回。

另外，工具结果同时保存在官方 checkpoint 和自建的依据存证表，每次工具调用前查询存证、每次载入会话与开始运行时对账。它的主要用途是停止或进程退出时找回并行工具中已完成的结果；实验确认官方 checkpoint 的 pending writes 已保存这些结果，并能从 `get_state().tasks[].result` 读回。

## 决定

- 每个 Run 在后台任务中执行；SSE 连接只订阅事件，断开不取消。新增接回接口，补发最近一次图状态及其后的消息事件。取消只来自取消接口和服务关闭。
- 删除自建依据存证与对账。停止或进程退出后，载入会话或开始下一轮时把 pending writes 中已完成的工具结果经官方 `update_state` 提交进 checkpoint；传入完整可见消息，避免仍有未完成任务时已提交结果被覆盖。
- 测点结论索引与测点调查记录作为 checkpoint 的派生索引，在工具完成时写入；从历史 checkpoint 分叉时删除被替换分支的索引。
- SSE 运行期间只实时转发消息事件，完整图状态只在结束和接回时发送，避免每一步重复传输全部依据。

## 影响

刷新页面不再中断调查。数据库不再为每次取数复制一份依据，旧存证表保留不读写。历史会话不做迁移：旧版本只存在于存证表、未进入 checkpoint 的结果不再自动找回。
