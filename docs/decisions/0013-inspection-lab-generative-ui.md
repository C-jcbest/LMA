# 0013：巡检原型——生成式 UI 流式巡检与视觉初判

- 日期：2026-11-17
- 状态：试验中；视觉模型部分取代 [0006](0006-remove-vision-and-plan.md) 的“删除视觉复核”

> 决策记录保存当时的背景与理由，是历史，不是现行规则的来源。现行架构见 [architecture.md](../architecture.md)。

## 背景

今日页的初筛理由是一长串分号拼接的句子，调查理由与数据质量混在一起，几百毫米后又恢复的跳点与真实台阶同样显示。用户希望巡检能给出简要结论，可选全部、按组、单站，并在点击巡检后流式输出界面与内容，而不是轮询列表。

## 决定

- 初筛结果增加结构化 findings；跳出后回到原水平的单次跳变改为数据质量（异常跳点），不作为建议调查的理由。
- 新增侧栏“巡检原型”页，与正式巡检并存：后端 LangGraph 图用官方 `push_ui_message` 推送汇总卡片与测点行，前端用 assistant-ui LangGraph Runtime 的 data part 渲染。布局由程序决定，模型只填组件内的文字，不让模型生成界面结构。
- 恢复视觉模型，但只用于原型中建议调查的测点：服务端画 90 天每日位移图（极端点贴边标记、缺测着色），模型给一句形态与数据质量初判；数值以初筛为准，初判不改变初筛状态。
- 调查对话里的依据卡片不改为推送组件，仍从工具结果的 artifact 渲染，避免同一数据存两份。
- 原型结果不写正式巡检表，不与旧格式兼容；是否并入今日页由试用结果决定。

## 理由

assistant-ui 与 LangGraph 已在项目中使用，生成式 UI 无需新框架；A2UI、json-render 等由模型决定布局的方案与设计规范冲突且难以测试。视觉模型此前因与数值特征重复而删除；这次只回答“图形像什么、数据是否可疑”，用于区分真实位移与数据异常，先在原型中检验价值。
