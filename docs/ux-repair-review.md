# 体验复审整改（2026-11-11）

## 用户可见变化

1. 首页输入作为新调查入口，发送时才切换官方会话运行时；首页与旧会话草稿分开，浏览不创建数据库会话。
2. 测点数据与会话加载失败隔离。会话不可用时仍可查看图表、调整数据窗口和返回；依赖会话的追问暂不可用。
3. 续查可见消息只显示“继续调查”。调查 ID 经独立请求字段传递，服务端校验会话归属和状态后存入不可变消息元数据，仅模型可见，不修改系统提示词。
4. 数值比较改为“共同有效时段比较”，不在未验证时暗示同组关系。
5. 恢复提示位于当前会话输入区，不覆盖顶部导航、外观图标。新请求尚无 AI 输出时，不把上一条回答标记失败。
6. 没有待解决项时省略该行，不再把已完成调查显示成“尚未记录”。
7. 复制、导出统一提供可读依据目录，包括测点、时间范围、采样和已取得的来源信息；不导出失效的应用内引用锚点。依据说明移到查看依据后的面板，正文减少重复标签。
8. 测点历史与首页“上次调查”按 UUID 查询关联；新增调查关联从成功工具产物的稳定标识建立。

窄屏测点标题不再重复显示；数值、天气、视觉引用打开对应明细页签，而不是默认落到另一类图表。

## 迁移约束

新增 `lma_station_record_links` 保存调查记录与测点 UUID 的关系，原记录和会话正文保持不变。通过既有一次性入口 `python -m app.server.storage` 迁移。

经用户明确确认，旧记录只从原回答所在轮的 checkpoint 工具证据恢复关联。同名对应多个 UUID、原证据缺失或历史已压缩时，不猜测、不按当前目录回填，也不增加名称回退查询；这些会话仍在“记录”页保留。迁移可重复执行，已有关联不重复插入。

新关联表引用原调查记录，删除会话时沿原有外键级联删除。仅从已完成调查建关联，不把工具目录列表当作调查结论。

## 验证

- 隔离 PostgreSQL 后端全量 145 项通过，包括原证据恢复关联、幂等迁移、同名不同 UUID、无证据旧记录保留、续查上下文隐藏。
- 前端单元测试 51 项通过。保留原有超时阈值，限制文件并发为 2；一次与浏览器测试同时运行时仍出现既有 5 秒超时，单独完整重跑通过，不宣称已根除偶发测试超时。
- 浏览器全量 46 项通过；最终错误处理、截图及窄屏标题调整后，调查相关 25 项与最后 3 项重点场景复核通过。发布 CI 再执行完整测试和生产构建。
- TypeScript、生产构建、git diff --check 通过。受影响函数与调用处已做可读性复查。
- 生产组件加模拟 API 验证首页新建调查、旧草稿保留、局部 503 故障恢复、续查可见消息、完成状态及顶部控件可操作。真实隔离 API 回归验证生命周期与测点会话独立性。

## 再次审视的边界

这次重点改善操作对象、页面状态与用户预期的一致性，不添加推荐问题、思维链或解释小字，不限制普通回答的表达形式。

仍需关注：

- 实际模型能否准确区分单站覆盖与共同有效覆盖、保持结论重点；前端和契约校验不证明自然语言判断完全正确。
- 证据面板内部的测点分组仍以显示名称组织，同一次回答出现同名不同测点时需进一步完善展示身份；本轮修复的是历史记录归属，不声称该展示场景已解决。
- 部分入口包与图表/地图包仍较大。当前已验证布局和交互，不把构建体积警告换算成未经测量的手机耗时。
- 浏览器测试出现外部瓦片请求失败及一条 ResizeObserver 通知警告；图表交互测试通过不等于外部地图服务稳定。
- iPhone Safari 真机键盘、手势和真实业务资料下的结论质量需独立验收。
