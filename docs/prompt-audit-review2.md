# LMA 提示词与上下文二审

审查基线：提交 3b18892 的工作区。二审接续 2026-11-10 首审，按当前源码重新判断，不沿用首审的问题数量和严重程度。完整原文见[二审原文清单](prompt-inventory-review2.md)。本轮只生成审查材料，不修改生产提示词或业务逻辑。

## 结论

新版明显更接近目标：用目的解释原则，让模型自主选择调查路径与回答形式；保留事实、口径和证据边界。无需继续增加大量“不得”和异常情况清单。

剩余问题主要在上下文与程序契约之间：当前任务的证据可能被压缩掉；页面所指的对象、窗口和线索没有完整进入上下文；部分反馈文字与实际权限不一致。另有少数程序校验把合法表达拦掉，或把没有观察内容的输出视为结构有效。应先解决这些具体问题，再进行小范围文案调整。

## 仍需处理的具体问题

### R1：本轮证据会在压缩后失去简报引用资格｜高，已复现

位置：[summarization.py](../backend/app/agent/summarization.py)、[report.py](../backend/app/agent/report.py) 的 _current_turn_evidence / _validate_report。

官方摘要按 token 和消息配对切分，不保护整个活动调查。简报只从当前消息中收集 ToolMessage，摘要不能恢复其引用资格。新提示词已经告知摘要中的编号失效，但这只解释了限制，没有保住活动任务所需的证据。

本轮用真实摘要中间件与简报校验、脚本摘要模型做了隔离复现：

- 同一轮先后取得 c1、c2 两条证据；压缩前引用 c1 的简报通过校验。
- 降低阈值触发压缩，近期只保留 c2。
- 相同简报随后被拒：依据编号 E2f2276 不存在。

这是机制复现，不代表默认阈值下已在线上发生。

建议明确活动调查的证据生命周期：压缩不能让仍需交付的依据突然失效。根据实际任务规模选择保护活动证据，或提供可追溯的证据定位与取回方式；不必直接上复杂记忆框架，也不应靠模型一遍遍重查。

相关已知限制：error 状态的部分结果即使包含有效事实也不获得依据编号。隔离检查中，部分结果正文仍可见，但可引用证据数为 0。新版明确禁止引用，因此现在属于保守的产品限制，而不是隐含契约冲突。若要求简报完整表达“已有证据 + 缺失部分”，再调整证据粒度；不建议把所有 error 结果直接当成功证据。

### R2：页面上下文只传站名，不能完整表达用户指向｜中，源码确认

位置：[StationPage.tsx](../frontend/src/features/stations/StationPage.tsx)、[AssistantProvider.tsx](../frontend/src/app/providers/AssistantProvider.tsx)、[message_context.py](../backend/app/agent/message_context.py)。

新增 focus_station 是正确方向，但当前只携带站名。页面已经知道 stationUuid、7/30/90 天窗口、时间序列和初筛原因，这些没有随普通提问一起传入模型。

具体影响：

- 用户看着 30 天图问“这段变化如何”，模型只知道站名，无法得知“这段”的窗口。使用图表“追问这段”按钮时会显式生成时间范围，该入口不受这一点影响。
- 页面已按 UUID 定位，模型却只能重新按名字匹配；重名或模糊匹配时仍需确认。
- 当前一键调查只发送“调查某站的近期变化”；页面初筛线索并没有送入模型。主提示词中“用户消息里的初筛线索来自批量巡检”的描述也不能用于认证任意用户手写文字的来源。
- 对话刚谈过 B 点、页面仍打开 A 点时，“问题未指明站名就用 focus_station”可能覆盖自然对话里的明确指代。是否实际误选需要真实模型评估。

建议传递解决指代所必需的最少上下文：稳定对象标识、相关显示窗口；确需利用初筛时再附来源时间和线索。不要把整页原始数据都塞入提示词。对象选择以当前明确要求和可确定的对话指代为先，页面焦点用于补足缺省信息。

### R3：查询额度耗尽后的反馈仍禁止提交简报｜中，文字冲突已确认

位置：[graph.py](../backend/app/agent/graph.py) 的 QueryCallLimitMiddleware，以及官方 tool_call_limit.py。

执行逻辑允许简报不计入查询额度，系统提示词也明确这一点；但框架实际生成：

> Tool call limit exceeded. Do not make additional tool calls.

这把“不能再查询”扩大成“不能调用任何工具”。模型可能据此放弃仍可提交的简报。此次直接核验了框架反馈，未用真实模型测量发生概率。

建议让反馈准确表达仍允许的操作，而不是继续给主提示词加例外。最后一次模型调用另行撤掉全部工具并要求直接作答，是不同预算下的合理结束机制，不应和查询额度混为一谈。

### R4：数据追问一律重查，仍比任务需要更僵硬｜中，设计取舍

位置：[system.md](../backend/app/agent/prompts/system.md) 的“追问需要用到监测数据时重新查询，不直接沿用之前的结果”。

刷新当前状态合理，但固定历史窗口的比较、解释采样差异、重组已有表格未必需要重新取数。当前规则把“当前证据可能过时”和“旧结果一定不可用于数据追问”合在一起，也掩盖了简报只能引用本轮证据的技术限制。

建议按目标判断：当前状态、用户要求刷新、对象/窗口/口径改变、时效不足时重查；历史分析可使用可追溯的既有证据。若保留每轮重查是明确业务要求，则接受其成本即可，不应当作普遍正确的上下文管理原则。修改策略时必须同时对齐引用机制，不能只放宽一句提示词。

### R5：关键词校验误拦合法否定句｜中，已复现

位置：[report.py](../backend/app/agent/report.py) 的 _FORBIDDEN_PATTERN / _validate_report。

使用有效站名和引用，结论写“不能认定已经发生滑坡”，校验仍以包含“已经发生滑坡”为由拒绝。这是对提示词要求的审慎表达产生直接干扰。

不建议继续穷举否定词和替代句式。应先界定这段程序检查到底保证什么，避免把子串命中当作语义越界。引用存在性、字段完整性可以确定性验证；灾害认定语义需要与任务风险相称的独立评估方式。

同时修正首审措辞：程序未证明事实正确不自动构成 bug；但若把现有校验称为“分层必须成立”或“事实真实保证”，就超出了实际能力。现有简报测试用空 GNSS 结果支持一条数值断言也能通过，说明它检验的是引用协议，而非事实支持关系。

### R6：空视觉对象能通过结构校验｜中，已复现

位置：[vision.py](../backend/app/agent/vision.py) 的 VisionObservations / _validate_observations / analyze_gnss_chart。

所有观察字段都有空默认值。传入 {} 后得到全部空数组和空字符串，结构校验不报错。后续路径没有要求至少存在一项有效观察或明确的不可判读说明。

“看过图、没有候选”和“没有返回任何观察”不是同一结果。不能仅凭空 candidates 断定正常；现有主提示词也没有允许这种推断。这里是输出有效性缺口，不是已证明模型产生了错误结论。

建议允许合法的无异常结果，但要求有基本的全窗观察或无法观察的明确原因。不要强制每份结果都填满所有数组。

### R7：上下文容量配置缺少相互约束｜中，源码确认

位置：[config.py](../backend/app/config.py)、[summarization.py](../backend/app/agent/summarization.py)。

默认触发 800000 tokens、保留 400000 tokens、摘要输出上限 2000 tokens，模型窗口独立配置；参数只有单项范围限制。待摘要内容不裁减。若换成较小窗口的模型却没有同步修改阈值，会在压缩之前超出容量；保留量接近或超过触发线也缺少约束。

这只是可配置出的风险，不代表当前部署已经超限；本次未读取 .env 或线上生效值。摘要的保留优先级已修好，不能继续声称其缺失。

建议验证配置关系并为系统、工具声明和单次工具结果预留容量。实际误差和余量通过真实请求评估，不能把近似消息计数与供应商实际输入 token 当成完全相同。

### R8：数值工具与“按需视觉”原则仍有轻微张力｜中，能力设计

位置：[system.md](../backend/app/agent/prompts/system.md)、[tools.py](../backend/app/agent/tools.py)、[vision.py](../backend/app/agent/vision.py)。

主提示词已经说明精确形态特征来自图形复核，并允许缺少时用基础摘要定性描述，合理地补上了行为出口。但视觉仍是取得鲁棒斜率、最大单步等特征的必经路径，且要等视觉服务成功。“只问数值或趋势时通常不需要”把天气、场地、视觉放在同一组，会让是否取数更难判断。

建议短期按需要的证据描述能力：“需要精确形态统计时使用能提供它的能力”。是否将确定性数值分析从视觉服务中分离，应按真实需求决定，不为提示词整齐而新增一层工具。

## 文案层面的精简建议

新版已经有较好的原则式表达，不建议再整体重写。可局部收敛：

- “固定时刻可以避开日内周期波动”偏绝对，宜表达为减少不同观测时刻带来的日内周期影响；不能保证完全消除。
- “不确定性说清一次即可”适合作为反重复原则，但不同站点、时间窗可能有不同证据缺口，不能理解成全报告只允许出现一次限制。
- 视觉图本身不能证明具体诱因这一边界值得保留；列举少量降雨、开挖等例子并非问题，无需因为出现枚举就删除。
- 标题提示词总体适配其窄任务。48 输出 tokens 是否过紧仍待真实模型验证，不列为已确认缺陷。若首条问题仅为“稳定吗”，标题模型只拿正文而没有页面焦点，标题可能不够可识别，属于后续体验评估项。
- 分析所需的事实来源、时间、采样、基线、覆盖范围应尽量由结构提供；不要要求模型从散落的自然语言里反复重建。
