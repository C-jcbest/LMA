## 主要发现

| 优先级 | 问题与依据 | 建议 |
| --- | --- | --- |
| P1 | 天气查询被当前天气拖累。`weather.py` 使用 `asyncio.gather` 同时请求 forecast 和 archive，任何一个失败会使整个工具失败。最新会话两次天气工具均失败，日志为 TLS 连接阶段 `httpx.ConnectTimeout`。生产容器内复测 archive 返回 200（约 1.1 秒），forecast 与 elevation 均在 12 秒探测上限超时；Macrostrat 返回 200（约 2.8 秒）。 | 按查询目的拆分历史与当前天气请求；同时需要两者时明确定义部分成功状态，保留成功部分并标明缺失范围。不要把局部失败说成所有数据服务不可用。网络超时本身仍需排查出口与上游，不能靠隐藏提示解决。 |
| P1 | 部分场地资料已取得却无法从正文打开。`site.py` 在地形失败、地质成功时返回 error；`EvidenceMarkdown` 与 `hasEvidenceCard` 只接受 complete。最新会话正文使用了地质结论，但该引用落入缺失分支。 | 区分“有部分有效依据”与“全无结果”，让地质依据可核查，并明确地形缺失。 |
| P1（已修，未部署） | 工具仍声称断层图层可用。`site.py` 固定返回 `faults.available=True` 和构造线图层说明，当前地图已无对应图层；最新回答实际复述“断层图层可用”。 | 已删除不再提供的能力描述及契约字段，迁移前后端调用方，保留分析数据查询。 |
| P2 | 站名搜索区分大小写。`find_stations` 使用原始字符串包含判断，最新会话的 `scwm4`、`scwm`、`4号` 均返回空，直到查询全表才找到 SCWM-04。 | 至少统一大小写匹配；简称和零填充编号的规范化需要明确匹配与歧义规则。 |
| P2 | 手机首屏失败信息占据较多空间。390px 实际页面里，已展开的两条失败原因、恢复说明和查询记录位于调查结论之前；泛化“数据服务”文字也没有点明天气。 | 保留简洁的失败摘要，详细原因按需展开，直接标明受影响的数据类型。 |
| P2 | 单点长期分析与同组对比使用相同卡片标题、时间窗和采样说明。真实页面出现两张相同标题，`StepCard` 对所有 gnss_series 均使用相同标题，预览固定 `peers: []`。 | 在标题中区分“位移”和“同组对比”，核对入口与实际展示内容的一致性。 |
