## 待验证（需要能访问对应服务的环境）

- [ ] 监测平台：用真实模型调查核对站点/分组解析、GNSS 时间窗和缺测、台阶候选、水平位移方位；测点页核对 7/30/90 天曲线、缺测标注和响应时间；确认模型会把 `focus_station` 当作未指明测点时的调查对象。本机访问平台登录接口曾被断开。
- [ ] 巡检原型（生成式 UI + 视觉初判）：部署后在生产确认服务器已配置 VISION_*、逐站推送不被网关缓冲、刷新可接回；由用户判断视觉初判是否值得并入今日页。本地用真实平台数据跑通全部、按组和单站巡检，17 个测点约 12 秒完成。
- [ ] 巡检初筛校准：在真实数据上运行一次，核对建议调查的比例和原因，按结果调整 [screening.py](../backend/app/inspection/screening.py) 中的噪声倍数。定时巡检和提醒在校准之后再决定。
- [ ] 天气：在可访问 Open-Meteo 的环境验收“某天几点下雨”和降雨前后对照；评测未绑定天气工具。
- [ ] 高德地图：在能连接高德的环境查看下坡方向扇形、单点地图的同组参照点、位移回放和 3D 地形。重点确认 `terrain` 在 JSAPI 2.0 下是否有地形起伏；若需要 2.1Beta，再评估升级加载版本的影响。
- [ ] 坡向精度：坡向来自约 90 m 地形；有勘查报告的主滑方向时对照一次，决定是否需要人工登记主滑方向。
- [ ] iPhone Safari 真机：软键盘、安全区、横竖屏、会话抽屉与焦点、地图手势、失败提示与重试。
- [ ] 前端交互与动效（2026-11-16 设计规范整改）：部署后在生产确认静态资源返回 `Content-Encoding: gzip` 与 `/assets/` 的长期缓存头，主机网关同步 http2 模板；真实生成一轮回答，确认新到文字淡入、打开历史会话不整段闪动；深浅两套主题下检查页签、表格、抽屉与依据卡片折叠。
- [ ] 历史会话编辑：在真实服务中复核已有会话的首轮与多轮编辑、重新生成和刷新后历史一致，并确认被替换回答的测点结论已从测点页消失。
- [ ] 调查后台运行：生产环境中调查进行时刷新页面、关闭再打开，确认接回进度、最终回答完整，网关不缓冲接回流。
- [ ] 测点坐标：用真实台账核对是否存在纬度、经度字段颠倒的测点（天气代码注释曾称存在系统性颠倒）；后端只纠正纬度超出 ±90° 的可判定情况。
