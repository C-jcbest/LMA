# LMA 产品定位与路线图

产品定位、能力优先级、成功标准和最终原则。**这里是方向，不是实施任务**：开始任何一项之前需要用户确认范围；现行业务规则见 [产品规则](rules.md)，未完成工作见 [状态与待办](../status.md)。

**版本：V2.0**
**产品名称：LMA（Landslide Monitoring Agent）**
**产品定位：面向滑坡连续监测业务的智能调查与分析助手**

------

# 1. 文档目的

本文档定义 LMA 当前及近期迭代的业务目标、功能范围、分析流程、证据规则、交互要求和输出边界。

文中的测点编号和调查问答均为虚构示例。

LMA 不建设新的完整监测平台，而是在已有北斗/GNSS 监测平台之上，通过大语言模型 Agent 自动组织数据查询、趋势分析、多站对比、气象关联以及后续调查步骤，帮助监测人员快速理解监测数据中发生了什么，并发现值得进一步核查的变化。

系统核心目标不是替代专业人员完成最终灾害判定，而是降低连续监测数据调查的人工成本，提高：

- 缓慢形变发现能力；
- 异常复核效率；
- 多站点对比效率；
- 数据质量问题识别能力；
- 多源证据组织能力；
- 日常巡检的一致性；
- 分析过程的可追溯性。

------

# 2. 产品定位

LMA 定位为：

> **面向滑坡连续监测场景，以 GNSS/北斗位移数据为核心，结合气象、空间地形和后续地质资料进行多源调查的 LLM Agent。**

系统主要回答：

> 当前监测点发生了什么变化？
> 这种变化是否持续？
> 与过去相比是否异常？
> 与同组其他监测点相比是否具有局部性？
> 当前是否存在加速迹象？
> 数据是否可靠？
> 是否存在需要人工进一步调查的线索？

系统可以基于已有证据进行审慎的滑坡相关分析，例如：

- 某点存在长期持续位移；
- 当前变化更符合缓慢变化而非短时跳变；
- 近期变化速率有所增加或降低；
- 该点变化明显区别于同组监测点；
- 某次降雨与位移变化在时间上接近；
- 当地坡向与位移方向具有一定一致性；
- 当前现象可能与坡体缓慢变形有关。

但这类内容必须明确属于**分析推断**，不得与直接观测事实混写。

# 23. 当前核心能力优先级

## P0：当前核心能力

必须稳定完成：

- LangGraph 多轮 Agent；
- 监测点/分组查询；
- GNSS 数据查询；
- 固定时刻长期趋势分析；
- 小时级细节分析；
- 数据完整性检查；
- 固定参考坐标累计位移；
- 数值特征与台阶识别；
- 同组对比；
- 天气查询；
- 综合调查回复；
- 会话流式管理；
- 按需核查依据。

## P1：近期重点增强

优先增加：

- 慢速形变双窗口分析（已实现：默认近期 7 天小时级 + 90 天每日固定时刻）；
- 站点历史自适应基线；
- 共模异常自动识别（巡检初筛已有同组共模判断，待真实数据校准）；
- 地图站点展示（已实现）；
- DEM 高程/坡度/坡向（已实现，约 90 m 分辨率）；
- 位移矢量地图展示（已实现，含下坡方向与时间回放）；
- 日常巡检模式（已实现手动巡检，定时巡检待定）；
- 更结构化的调查状态（已实现结论登记）。

## P2：后续研究能力

可进一步研究：

- 地质图与岩性资料；
- 多类传感器联合；
- 现场巡查记录；
- 地下水；
- 裂缝；
- 深部位移；
- InSAR；
- 自动风险模型；
- 滑坡阶段识别；
- 预测模型。

P2 中风险预测类能力必须经过单独实验验证后才能进入正式业务结论。

# 26. 产品成功标准

LMA 的成功不以“模型说出了滑坡”衡量。

真正需要提高的是：

1. 是否能够正确找到相关监测数据；
2. 是否能够发现缓慢持续变化；
3. 是否能够区分局部变化与多点共模变化；
4. 是否能够识别数据质量问题；
5. 是否能够避免把单点尖峰当成持续变化；
6. 是否能够正确组织天气、地形等辅助证据；
7. 是否能够避免无证据的确定性推断；
8. 是否能够让监测人员快速知道“应该先看什么”；
9. 相同数据重复分析时，核心事实是否稳定；
10. 数据缺失和工具失败时是否能够安全降级。

------

# 27. 最终产品原则

LMA 不应成为：

> 一个看到曲线后替监测人员宣布“发生滑坡”的聊天机器人。

而应成为：

> 一个能够主动获取证据、扩展时间窗口、比较历史趋势、检查同组站点、识别数据问题、调用气象和场地资料，并将事实与推断清晰区分的滑坡监测调查 Agent。

其核心价值是：

**更早发现值得关注的变化、更快完成异常调查，并把最终专业判断需要的证据准备好。**
