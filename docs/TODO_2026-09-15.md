## 一、总原则

所有复杂事项实施前统一执行以下判断：

1. **先定职责层**
   Thread / Run / Checkpoint / ToolMessage 属于 Agent Server / LangGraph；模型调用、工具调用、重试与中间件属于 Agent Runtime；UI 只负责投影与交互，不反推业务事实。

2. **优先官方能力**
   能由 `create_agent`、middleware、`useStream`、Thread API、Run API、标准 `content_blocks`、ToolMessage 协议完成的，不自建第二套状态机。

3. **优先删除而不是兼容**
   新增 fallback 前必须说明：
   - 为什么官方能力无法覆盖；
   - fallback 的触发条件；
   - 权威事实来源；
   - 用户可见行为；
   - 何时可以删除。

4. **Agent Chat UI 只参考职责划分与交互，不机械复制实现**
   当前 LMA 使用 `@langchain/react v1`，而 Agent Chat UI 主分支仍存在不同 SDK/Hook 写法。优先级应是：
   1. 当前项目锁定版本官方文档；
   2. 当前包的类型定义/API；
   3. Agent Chat UI 的交互与职责设计；
   4. Agent Chat UI 的具体代码写法。

5. **业务错误、基础设施错误、UI 错误分层处理**
   不把所有失败最终都汇总成一条红框，也不把内部异常直接展示给普通监测人员。

6. **每次只处理一个复杂事项**
   定向测试通过后停止并汇报，不自动推进下一项。

## TODO 6：标准化 Tool 协议——参数错误、业务错误、基础设施错误必须区分

当前很多工具直接：

`return "未找到站点..."`

从 Agent Runtime 视角这是一次成功工具调用，前端却可能显示 `finished/success`。

必须统一 Tool 协议。

### 参数错误

例如：

- 非法时间格式；
- 非法枚举；
- 非法 sample_times；
- begin > end。

优先通过 Tool/Pydantic schema validation 表达，不依赖工具函数内部大量字符串判断。

### 可预期业务失败

例如：

- 站点不存在；
- 名称不唯一；
- 基准站不适用位移分析；
- 查询窗口内无数据；
- 外部数据源明确返回“无数据”。

必须形成标准 Tool error 语义，而不是普通 success 内容。

### 瞬时基础设施失败

例如：

- timeout；
- connection reset；
- 502/503；
- rate limit。

抛出可识别异常，交由工具重试 middleware。

### 内部程序错误

- 不把 Python exception、URL、stack、内部字段直接返回模型/前端。
- 写完整日志。
- 对模型使用受控错误文本。

### Tool 返回结构

优先统一为：

- `content`：给模型看的精简事实；
- `artifact`：给 UI/调试层的结构化数据；
- `status`：由标准 ToolMessage 表达。

避免：

- 普通字符串；
- JSON 字符串；
- artifact；
- detail；
- raw；
- preview；

多套并存。

**验收**

- “站点不存在”前端显示 tool error，而不是 success。
- Tool lifecycle 可以完全由官方 status 投影。
- 模型仍能理解错误并继续降级回答。

## TODO 7：将 Tool/Model retry 从节点级重试调整为调用级 middleware

原 `RetryPolicy` 挂在整个 `tools` Node；TODO 4 已移除，接入官方 ModelRetryMiddleware / ToolRetryMiddleware，单调用重试与 HTTP Stub E2E 已通过。TODO 7 继续完善工具/供应商瞬时错误分类和整体重试预算，避免底层客户端、视觉调用与 middleware 叠加重试。

并行工具场景：

- A 已成功；
- B timeout；

节点级 retry 有可能导致整个 tools node 重跑，从而重复执行 A。

### 推荐方案

优先采用：

- `ToolRetryMiddleware`
- `ModelRetryMiddleware`

做到：

- 哪个 tool 失败只重试哪个；
- 模型 API 失败只重试模型；
- 业务错误不重试；
- 参数验证错误不重试。

同时增加：

- `ToolCallLimitMiddleware`
- `ModelCallLimitMiddleware`

用于防止：

- 工具无限循环；
- 模型异常反复规划；
- 视觉候选造成无限外部请求。

**验收**

- 并行 A 成功、B transient failure 时 A 不重复执行。
- 重试次数、backoff、最终失败有独立测试。
- 不把业务错误当 transient retry。

# 四、第三阶段：重新基线化 `useStream` / Thread 生命周期

## TODO 8：新会话改用 `threadId=null -> submit -> onThreadId`

当前流程：

1. UI `crypto.randomUUID()`
2. `threads.create()`
3. 本地登记 pending Thread
4. `stream.submit()`
5. 后台生成标题

这造成：

- `isNewSessionDraft`
- `pendingThreadId`
- `titleGenerationIdsRef`
- create 成功但首个 Run 失败留下空 Thread
- UI 与 SDK 双重 Thread 生命周期

### 推荐方案

新会话：

1. 当前 `threadId = null`
2. 用户直接 `stream.submit()`
3. SDK/Agent Server 创建 Thread
4. `onThreadId(id)` 接收真实 ID
5. 写入 URL
6. 刷新 Thread 列表

删除手工预创建 Thread 的必要性。

### 标题

标题生成仍可作为独立 threadless assistant，但：

- 不阻塞主 Run；
- 失败静默回退“新会话”；
- 不污染聊天错误；
- Thread 创建后再异步更新 metadata。

**验收**

- 首条消息失败不遗留无意义空 Thread。
- 不再需要 pendingThreadId 等临时状态。
- 新建 → 首条消息 → 获得 thread id 链路完全由 SDK 负责。

# 十三、最终目标架构

```text
Browser / React
    |
    | @langchain/react useStream
    | Thread / Run / Tool / Message official projections
    v
LangGraph Agent Server
    |
    | Thread / Checkpoint / Run lifecycle
    v
LangChain Agent Runtime
    |
    | create_agent
    | middleware
    |  - dynamic system prompt / runtime context
    |  - summarization
    |  - model retry
    |  - tool retry
    |  - model/tool call limits
    v
Domain Tools
    |
    +-- Beidou/GNSS
    +-- Weather
    +-- Vision
    +-- Site environment
    |
    v
Domain normalization + HTTP/session providers
    |
    v
Upstream monitoring / external evidence services
```

前端不负责：

- 修 checkpoint；
- 猜 Tool 是否取消；
- 猜 Run 状态；
- 构造业务事实；
- 兼容供应商 reasoning 私有字段。

Agent Runtime 不负责：

- UI recommendation 持久化；
- 地图 URL；
- 伪造错误结果。

Tool 不负责：

- 风险等级；
- 固定滑坡阈值；
- 把业务错误伪装成 success。

这样最终 LMA 的自定义代码只保留真正属于项目的部分：

- 滑坡连续监测 Prompt；
- GNSS/天气/视觉/场地环境领域工具；
- 数据规范化；
- 轻量客观特征；
- 业务 UI Renderer；
- 上游平台适配；

而 Thread、Run、Agent loop、tool lifecycle、retry、context summarization、stream/rejoin、optimistic message 等通用能力尽可能交给 LangGraph/LangChain 官方实现。
