## 一、总原则

所有复杂事项实施前统一执行以下判断：

1. **先定职责层**
   Thread / Run / Checkpoint / ToolMessage 属于 Agent Server / LangGraph；模型调用、工具调用、重试与中间件属于 Agent Runtime；UI 只负责投影与交互，不反推业务事实。

2. **优先官方能力**
   能由 `create_agent`、middleware、`useStream`、Thread API、Run API、标准 `content_blocks`、ToolMessage 协议完成的，不自建第二套状态机。

3. **优先删除而不是兼容**
   新增 fallback 前必须说明：
   - 为什么官方能力无法覆盖；
   - fallback 的触发条件；
   - 权威事实来源；
   - 用户可见行为；
   - 何时可以删除。

4. **Agent Chat UI 只参考职责划分与交互，不机械复制实现**
   当前 LMA 使用 `@langchain/react v1`，而 Agent Chat UI 主分支仍存在不同 SDK/Hook 写法。优先级应是：
   1. 当前项目锁定版本官方文档；
   2. 当前包的类型定义/API；
   3. Agent Chat UI 的交互与职责设计；
   4. Agent Chat UI 的具体代码写法。

5. **业务错误、基础设施错误、UI 错误分层处理**
   不把所有失败最终都汇总成一条红框，也不把内部异常直接展示给普通监测人员。

6. **每次只处理一个复杂事项**
   定向测试通过后停止并汇报，不自动推进下一项。

## TODO 7：官方重试与单轮调用预算（已完成，2026-09-15）

- 主模型/单工具使用官方 ModelRetryMiddleware / ToolRetryMiddleware；仅重试网络中断、超时及 HTTP 408/429/500/502/503/504。参数、权限、业务拒绝、空数据、内部程序错误和混合非瞬时异常组不重试；请求本地协议错误不误判为网络瞬时失败。
- AGENT_MAX_RETRIES 默认2，最多3次尝试；官方指数退避初始0.5秒、倍率2、基础延时上限4秒，并采用官方±25%抖动。失败耗尽由既有安全边界说明限制，不暴露内部异常。
- 官方 ModelCallLimitMiddleware 默认每Run最多20次主模型调用，达到上限显式报错；ToolCallLimitMiddleware 默认每Run最多40次工具调用，超额调用返回官方error，允许的并行调用仍执行。只设置run_limit，下一轮重新计数，不限制整个会话寿命。官方限额统计逻辑调用，重试次数另算：默认主模型最多60次尝试、工具最多120次尝试；不将其称为全部HTTP请求或耗时上限。
- 主模型、视觉、标题、推荐及摘要的底层SDK均max_retries=0。标题/推荐一次调用；摘要仍遵循用户指定的官方SummarizationMiddleware逻辑，独立于主模型重试和调用计数。
- 视觉每次工具尝试只调用一次模型。已删除格式校验/空结果重试和降载重试内容构造；这些失败直接返回error并保留图表。有效候选默认最多12个，超额时明确拒绝数值回查、提示缩小窗口，不静默裁掉候选。候选回查并发仍最多5；每个合法候选最多一次回查/工具尝试，整体受工具调用数与重试数约束。
- 北斗的会话过期认证刷新最多一次，是认证协议行为，不扩展为通用失败重试；HTTP客户端不附加重试。
- 用户只看到中文调用限制和受控失败说明；官方计数字段、英文限制消息、服务URL和堆栈不作为界面展示。工具超额依官方status投影，模型仍可依据已有证据回答。

**验证**：生产回归覆盖成功并行工具不重跑、错误分类、两层官方退避、重试耗尽、模型循环终止与下一轮恢复、工具超额配对和主usage保留、视觉非瞬时错误/候选超额不重试；真实Agent Server/SDK验证工具超额及ModelCallLimitExceededError；前端验证中文限制和内部错误隔离。

## TODO 12：Stop 取消当前 Run 并清除未完成 tool calls（已完成，2026-09-16）

- `stream.stop({cancel:true})` 只以官方默认 interrupt 取消已知当前 Run。Stop 不是 HITL，不存在 resume；不使用 rollback，不扫描 running/pending Run，不批量 cancel。切换会话仍用 disconnect，服务器 Run 继续。
- 记录 onCreated 的当前 runId；Stop 后仅 join 该 Run，确认最终 checkpoint 后清理，避免与迟到工具结果竞态。思考阶段或工具全部完成时不写 checkpoint，重复 Stop 同步防重。
- 检查最终 checkpoint 中全部 AI tool-call 消息，不以最后一个 HumanMessage 为起点；否则失败重试先追加的新 HumanMessage 会遮蔽旧残留。ToolMessage 只有紧随对应 AIMessage 的连续工具结果才算有效配对。batch 全部未完成时写 RemoveMessage 删除该 AIMessage；多个未完成 AIMessage 分别删除。并行 batch 部分完成时原位收窄 AIMessage，只保留已成功配对的 calls，成功 ToolMessage 原样保留。
- 不生成 cancelled ToolMessage，不使用 asNode="tools"，不保留 cancelled Tool UI 状态，也不根据 Run inactive 推断工具取消。清理后重新 hydrate 权威 checkpoint，未完成工具自然消失。
- 下一条 HumanMessage 仍是普通 `stream.submit({messages:[HumanMessage]})`，以 multitaskStrategy=reject 创建新 Run，不发送 Command 或 resume。
- 主动 Stop 导致的旧 submit 迟到错误不得覆盖清理结果或下一 Run。若前端流异常但服务端已确认同一 runId，读取该 Run 状态；running/pending 只 join 该 Run，success 后 hydrate 权威 checkpoint，真实 error 才显示失败。不得自动重试或另建 Run。取消前工具结果、下一条 HumanMessage 与新 Run 的 AI 回复必须保持独立消息边界。

**实现边界**：锁定版 `@langchain/react` 尚无公开的“外部 updateState 后刷新当前 Thread”方法；当前通过其导出的 STREAM_CONTROLLER 调用 hydrate。触发条件仅为 Stop 清理成功，用户可见行为是立即从权威 checkpoint 重投影。该最窄版本适配不伪造状态；TODO 15 改用官方消息投影时复核并在公开刷新 API 可用后删除。

**验证**：前端58项测试覆盖思考阶段、单批/多批未完成、失败重试追加 HumanMessage、并行部分完成、严格相邻配对、总结前停止后的消息边界、主动 Stop 迟到错误、流异常后同 Run 成功恢复、全部完成、重复 Stop、清理失败、重新 hydrate 及下一条普通 submit；真实 SDK wire-format 回归约束 RemoveMessage 必须序列化为 lc constructor，payload 无 ToolMessage/asNode/Run扫描。生产构建通过；后端常规51项中49项通过、2项Server E2E默认跳过。真实本地 Agent Server 已验证 lc constructor 可删除目标 AIMessage并保留 HumanMessage；受影响会话的全部残留也已清理并读回确认。完整真实浏览器 E2E 仍属后续验收。

```text
Browser / React
    |
    | @langchain/react useStream
    | Thread / Run / Tool / Message official projections
    v
LangGraph Agent Server
    |
    | Thread / Checkpoint / Run lifecycle
    v
LangChain Agent Runtime
    |
    | create_agent
    | middleware
    |  - dynamic system prompt / runtime context
    |  - summarization
    |  - model retry
    |  - tool retry
    |  - model/tool call limits
    v
Domain Tools
    |
    +-- Beidou/GNSS
    +-- Weather
    +-- Vision
    +-- Site environment
    |
    v

    |
    v
```

前端不负责：

- 修 checkpoint；
- 猜 Tool 是否取消；
- 猜 Run 状态；

- UI recommendation 持久化；
- 地图 URL；
- 伪造错误结果。

Tool 不负责：

- 风险等级；
- 固定滑坡阈值；
- 把业务错误伪装成 success。

这样最终 LMA 的自定义代码只保留真正属于项目的部分：

- 滑坡连续监测 Prompt；
- GNSS/天气/视觉/场地环境领域工具；
- 数据规范化；
- 轻量客观特征；
- 业务 UI Renderer；
- 上游平台适配；
